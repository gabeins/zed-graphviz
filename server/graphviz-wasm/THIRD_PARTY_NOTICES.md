# Third-party notices for graphviz.wasm

`graphviz.wasm` is a WebAssembly build of the Graphviz `dot` command. It is
produced by [`build.sh`](build.sh) and is embedded in the `graphviz-preview`
language server. It is **not** covered by this repository's MIT licence: it
is a separate program, distributed under the Eclipse Public License 2.0
together with the permissive licences of the libraries compiled into it.

The language server talks to the module only through its command-line
interface (arguments, standard input, standard output and standard error).
No Graphviz source code is part of the server.

These are part of the Graphviz 16.1.0 release and are compiled in. Their
notices are kept here because their licences ask for that in binary
distributions.

- `lib/neatogen/randomkit.c` (Random kit 1.3, Mersenne Twister): BSD-3-Clause
  style and MIT notices; see
  [licenses/Graphviz-randomkit.txt](licenses/Graphviz-randomkit.txt).
- `lib/rbtree/` (red-black tree by Emin Martinian): permissive notice; see
  [licenses/Graphviz-rbtree.txt](licenses/Graphviz-rbtree.txt).
- `lib/cgraph/grammar.c` and `lib/common/htmlparse.c` are generated by GNU
  Bison. They are GPL-3.0-or-later WITH Bison-exception-2.2; the exception
  allows the generated parsers to be distributed under the terms of the
  surrounding program (here EPL-2.0).

### Not included

The build disables everything that would bring in other licences: no GTS
(LGPL), no cairo, pango, gd, fontconfig, freetype or zlib, and no
`ipsepcola` (its sources in `lib/neatogen` and `lib/vpsc` are under the
Common Public License and are compiled out). The C++ files Graphviz builds for
`dot` use no C++ runtime, so no libc++ or libc++abi code is linked. Graphviz's
`libltdl` (LGPL) is not built.

## Source code for graphviz.wasm

Graphviz is available under the Eclipse Public License 2.0. The complete
corresponding source for `graphviz.wasm` is:

1. the Graphviz 16.1.0 release tarball (URL and SHA-256 in `build.sh`),
2. the patches in [`patches/`](patches), which are modifications of Graphviz
   and are therefore distributed under EPL-2.0, not MIT, and
3. [`build.sh`](build.sh), which pins and verifies every input (wasi-sdk,
   Graphviz, Expat) and records the configuration used.

Running `./build.sh` rebuilds the module from these sources.

Every release archive of the language server carries `build.sh`, the
patches and these notices in its `graphviz-wasm/` folder. The same files,
exactly as used for a release, stay available at the release's tag:
`https://github.com/gabeins/zed-graphviz/tree/v<version>/server/graphviz-wasm`
(for example `.../tree/v0.3.0/server/graphviz-wasm`). The archive's copy of
this file names the exact URL for that release.

## What EPL-2.0 asks of a release that embeds graphviz.wasm

The language server binaries published on GitHub releases contain
`graphviz.wasm` in executable (object code) form. Section 3.1 of EPL-2.0
then requires the distributor to:

- make the Graphviz source available, and accompany the binary with a
  statement that the source is available under EPL-2.0 and how to obtain it
  (the "Source code" section above is that statement);
- if the Graphviz part is offered under any licence other than EPL-2.0, use a
  licence that disclaims warranties and excludes liability on behalf of all
  Graphviz contributors, does not limit recipients' rights to the source,
  and requires later distributors to meet the same conditions. The simplest
  way to satisfy this is not to relicense at all: `graphviz.wasm` stays under
  EPL-2.0, and only the server's own code is under MIT;
- keep all copyright, attribution and warranty-disclaimer notices of the
  Program (section 3.3).

Section 3.2 adds that source copies of Graphviz (including the patches in
this directory) must carry a copy of EPL-2.0, which
[licenses/Graphviz-EPL-2.0.txt](licenses/Graphviz-EPL-2.0.txt) provides.

The MIT and BSD-2-Clause components above require their copyright and
permission notices to be included with binary copies. Each release archive
therefore ships this file, the `licenses/` directory, `build.sh` and the
patches next to the binary, and the extension unpacks the whole archive, so
the notices also sit beside the server on users' machines. The licences of
the Rust crates in the server are listed in the archive's
`THIRD_PARTY_RUST.md`.

This file describes how the licences apply to this build. It is not legal
advice.
